# SQ01～SQ07 完善与本地验收

日期：2026-09-05。本批完成页面入口、策略步骤和变更约束的代码与本地回归；没有部署。以下记录软件行为和验证范围，不代表施工参数、几何对称性或现场工艺已经审批。

## 变更内容

| 项目 | 当前行为 |
| --- | --- |
| SQ01 生产操作 | 下发前选择本焊序已批准的领用单；下发后冻结关联。生产面板支持派工、资格特批、过程记录/完工、电流/电压/焊速/热输入/预热及层间温度、实际焊材记录关联、检验页面入口和执行历史。失败保留输入；结果未知时把完整请求和幂等键保存在当前浏览器标签页的 sessionStorage，刷新重试复用同一请求。 |
| SQ02 执行前置条件 | 依据放行时冻结的依赖图检查前置任务完成及关联检验合格，客户端自行提交的质量快照不能代替检验结果。新增行锁串行处理同一任务的执行请求；同一键重放返回原记录，不同键也不能再次完成已结束任务。 |
| SQ03 封闭前检测 | 确认的最终封闭焊缝前增加封闭节点，内部焊缝的 NDE 是其前置条件。分段后 NDE 必须等待该焊缝全部分段完成，偏好顺序不能跳过检测。 |
| SQ04 资源实时有效性 | 保留每次执行时重读 WPS、焊工证书、设备状态和校准日期的检查；资格例外仅覆盖原审批范围。补充已结束任务或失效批次不得重新派工。 |
| SQ05 实际策略 | 分段/跳焊按焊缝已知长度生成独立焊接步骤、范围及任务。以 1250 mm、每段最大 500 mm 为例，区间为 0～500、500～1000、1000～1250；跳焊顺序为第 1→3→2 段。交错策略沿用同类焊缝两端交替顺序，并在分段时两端交替；顺序保存为强制依赖，不会被拓扑排序或拖动覆盖。 |
| SQ06 放行后的变更 | 申请→审批→重算→核对并批准新焊序→应用→新版本下发。申请审批状态在重算前同步；重算只绑定候选版本，不提前标为已应用。应用要求本申请生成的、当前数据版本的已批准冻结方案；旧批次变为 superseded，不能再执行，旧任务状态、冻结来源与执行历史保留。 |
| SQ07 结构与模板 | 依据工程师确认的零件角色和焊缝连接选用模板：存在筒体/封头连接才能选择容器模板，且必须明确实际最终封闭焊缝。结构不明确时采用通用焊接模板，不根据零件名称强行加入容器成形/封闭节点。连接、角色及选择依据保存在焊序策略快照。 |

## 操作路径

1. 在已批准的图纸版本完成 WPS/PQR 匹配，进入焊序编排。
2. “生成候选焊序”中选择结构模板、确认零件角色及最终封闭焊缝；需要分段/跳焊时输入每段最大长度。缺少有效焊缝长度会明确拒绝生成，单条最多 100 段、整体最多 2000 步。
3. 查看步骤依据、分段范围和前置依赖，按工作区审批规则批准冻结。
4. 生产面板选择领用单后下发。重复下发不能悄悄替换已冻结领用单。按依赖派工、填写检验、记录过程或完工，可在同页查看历史。
5. 已放行方案修改时，在原版本的“已放行焊序变更”中申请，批准后选择新的分段长度/策略重算。查看新版本、核对并提交审批后，回到原版本应用变更，再切换新版本下发。新批次不自动继承旧完工记录。

## 部署和边界

- 同步更新前后端即可，本批未新增表或列；结构与分段信息使用现有 JSON 快照，策略依赖使用现有 `manual` 类型。已有冻结方案及生产任务不会自动改写，需要按变更流程生成新版。
- 历史方案若没有结构快照，重新生成采用通用结构默认值；需要容器特定工序时应在新的方案中确认结构角色，不能仅凭名称推断。
- “对称”在本批指编号两端交错及线性分段两端交替，不是三维几何或热变形计算。分段起点、行进方向、实际对称位置以及施工工艺仍需人工确认。
- 温度等实际参数会保存，但完整的 WPS 范围比较与返修闭合仍属于 SQ15；本批没有把这些后续任务一并勾选。
- sessionStorage 恢复范围是同一浏览器标签页的刷新/重新挂载，不保证关闭标签页、换浏览器或清除存储后的恢复。服务端幂等与任务终态检查继续生效。
- 本轮未完成生产部署、企业审批页面的人工浏览器验收或车间现场联调；真实数据库、JWT 接口与前端组件验证应与这些范围区分。
