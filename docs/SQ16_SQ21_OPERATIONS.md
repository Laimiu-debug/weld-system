# SQ16–SQ21 本地验收与使用说明

## SQ16：审核后的多阶段热处理

在图纸审核页编辑焊缝要求，确认“需要热处理”，按先后顺序填写阶段计划。每阶段必须有编号、局部/整体范围、温度上下限、保温分钟数；可分别选择热前、热后检测方法。整体处理还须填写共同批组编号。计划最多 12 阶段，阶段编号不得重复，同批组同阶段的温度与保温时间必须一致。

已审核计划直接生成局部或整体 PWHT 节点，以及各阶段、各方法独立的强制检测节点。整体处理等待产品全部焊接及成员焊缝的热前检测完成；局部处理仅跟随对应焊缝。多阶段按计划依次连接；分段焊接时所有相关分段必须先完成。检测计划须覆盖焊缝已规定的检测方法。不能通过备注代替节点和依赖。

旧数据只有 `pwht_required=true` 而无阶段计划时，生成焊序返回明确的补充审核提示；不会继续推定整体处理。修改已批准图纸仍克隆新版本，计划随版本复制。计划表示审核后的施工要求，热处理记录仍须质量人员核验；没有接入炉温采集设备或自动判定温度曲线。

代码：[阶段生成](../backend/app/services/sequence_treatment_service.py)、[计划编辑](../frontend/src/pages/Engineering/TreatmentPlanEditor.tsx)。

## SQ17：来源变更影响

焊序详情、生产资格查询、放行批次和施工交付包检查以下来源：图纸数据/审核状态及新图纸版本，WPS 和 PQR 冻结字段，资格规则包版本/状态/新生成焊序保存的完整基线，以及最新批准匹配冻结和匹配所依据的图纸数据版本。

变化提示返回来源类型、来源 ID、受影响焊缝 ID 和图纸定位入口。来源过期时阻止提交旧焊序和新建放行批次。已放行批次继续保留原始图纸、焊序、工艺和领用单快照，仍可查看和导出；不会自动替换执行参数。施工调整沿用生产变更审批流程。历史焊序没有规则包完整基线时，只能核对当时保存的规则版本与状态，不能追溯补造旧规则内容。

代码：[影响检查](../backend/app/services/sequence_source_service.py)、[提示组件](../frontend/src/pages/Engineering/SourceImpactAlert.tsx)。

## SQ18：施工交付包

入口：图纸审核页选择焊缝 → 查看焊序与施工记录 → 生产面板“施工交付包 / 扫码定位”。也可从任意已放行焊序直接进入 `/engineering/sequences/{id}/delivery`。

交付内容包括发布批次与冻结哈希、图纸原页和位置坐标、焊缝编号、步骤编号、强制前置步骤、冻结 WPS 版本及 PQR 快照时间、分段/热处理参数、检验点及检验结果、返修复验、实际参数与焊工/设备/登记人 ID、冻结领用材料和实际焊材批次流水。

支持按焊缝/任务定位、导出当前筛选范围的自包含 HTML、导出完整 JSON、浏览器打印。HTML 包含内嵌 SVG 二维码及绝对系统链接，不需要脚本运行。二维码只定位到任务；查看与执行继续受登录、工作区和生产权限检查。选择步骤后通过既有执行表单确认，开工/完工继续检查依赖、资源、参数和质量闭合；成功登记后刷新交付记录。

导出内容反映生成时点；再次使用前可刷新。旧发布批次没有保存图纸/领用单快照时明确提示缺失，不用当前内容冒充历史资料。文件包含页码和坐标及图纸系统链接，未嵌入原始 PDF 全文。

代码：[交付数据](../backend/app/services/sequence_delivery_service.py)、[交付页面](../frontend/src/pages/Engineering/SequenceDelivery.tsx)。

## SQ19–SQ21：关联和并发保护

- SQ19：修改关系前锁定图纸版本并刷新关联零件，防止两个并发父级修改形成循环；继续拒绝跨版本、失效、不存在的零件引用，克隆时映射到新零件 ID。
- SQ20：普通任务更新、进度、生产记录及删除入口先刷新并锁定任务，再判断发布任务限制，防止旧会话把已完成状态回写为未完成。
- SQ21：批准特批时按任务、授权记录、发布批次加锁，重新检查申请新旧及资源有效性；旧申请不能覆盖新派工。与新派工同时提交时，最终保留新派工结果。派工和执行复查统一使用匹配快照的 `welding_position`，兼容旧 `weld_position`，避免漏检焊位资格。

没有自动修复历史错误关联或重写历史任务。授权角色和企业访问范围沿用现有规则。

## 数据库与验证

新增迁移 `add_sequence_treatment_plan`，前置版本 `allow_unknown_part_quantity`，增加可空 JSONB 字段 `weld_requirements.treatment_plan`。迁移不自动填充工艺计划；存在非空计划时拒绝直接降级删除。升级应经过既有迁移链，不得把旧业务库直接 stamp 到最新版本。本轮只在自动生成的 PostgreSQL QA schema 和临时表上验证，未修改现有业务库迁移版本。
